# Golden test data

`golden_compare` (ctest) runs every case in `cases.txt` through the C++ library,
**in order and on one shared state** (the original keeps state between calls),
and compares each result line with `expected.txt`.

| File | Content |
|---|---|
| `cases.txt` | 249 cases: `name \| C_mode \| bor_dis \| PD \| field=value;...`. Generated by `tools/golden/gen_cases.py`. `${FX}` is replaced by the fixture directory. |
| `expected.txt` | Expected results for **V7.21.5** (the Fortran in `fortran/`). |
| `expected_v7212_original_dll.txt` | Results of the original Compaq Visual Fortran DLL **V7.21.2** for the first 222 cases. Kept for reference: this is the ground truth the port was built against. |

Result line format: `name|err=<HCM_error>|<29 numeric outputs>|ver=..|txnew=..|rxnew=..|info=..|depol=..|seat=..`
(order of the numeric outputs: see `Outputs` in `include/hcmms/hcmms.hpp`).
Tolerances: 0 for error codes, heights and Hz; 1e-6 km for distances; 0.01 for dB/m/degree values.

The test data (`topo`, `morpho`, `border`) are synthetic and generated by
`tests/fixtures.cpp`; the `fixtures_generate` test checks their checksum.

## How `expected.txt` was produced

The original DLL exists only for V7.21.2, so the V7.21.5 data was derived and
cross-checked:

1. **Port vs. original:** the C++ port (built from V7.21.2) reproduced the original
   CVF DLL on all 222 cases (`expected_v7212_original_dll.txt`).
2. **V7.21.2 → V7.21.5 delta:** both Fortran versions were built with gfortran
   (`fortran/gfortran/`). The upstream changes alter 54 of the 222 cases
   (`rxnew` always set, `Rx_frequency = 0` accepted, `D_sea_calculated` init,
   'H' bandwidth designator, line buffer 1400). After porting these changes the
   C++ delta was **identical** to the gfortran delta on every case, and the
   remaining gfortran-vs-C++ differences (35 cases, gfortran runtime vs. Compaq
   runtime in formatted/list-directed READ) were identical before and after.
3. **Review probes (cases `probe_*`):** behaviour checked directly against the
   original DLL (number overflow → read error, null values in the bandwidth
   designation, fields without digits). The C++ result equals the original on all
   of them except the two 'H' cases, which are V7.21.3 functionality and match the
   gfortran V7.21.5 build.

## Regenerating

```sh
python tools/golden/gen_cases.py          # cases.txt (append new cases at the end!)
```

New cases must be appended: earlier results depend on the state left by previous
cases. To get reference results from a Fortran DLL (Windows only, the DLL is
called via P/Invoke; use a PowerShell matching the DLL bitness):

```powershell
.\scripts\test.ps1                          # builds and generates the test data in build\release\fx
.\fortran\gfortran\build.ps1 -Arch 32       # optional: build the Fortran reference DLL
C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe -File tools\golden\Invoke-Hcmms.ps1 `
    -DllPath fortran\gfortran\out\win32\HCMMS_V7_DLL.dll `
    -CasesFile tests\golden\cases.txt -FixtureDir M:/path/to/build/release/fx > reference.txt
```

Note that gfortran and the original CVF runtime differ in some READ edge cases
(see above), so a gfortran DLL is a cross-check, not a drop-in golden source.
